# リファクタ候補

## 2026-08-25 精査結果

| 候補 | 判断 | 実施内容・理由 |
|---|---|---|
| 非同期処理とゲーム状態の所有権 | 対応済み | `G` 自身に有効状態とクリアタイマーを持たせ、`endGameSession()` / `isCurrentGameSession()` へ終了・有効性判定を集約。`gameEpoch` とグローバルなクリアタイマーを廃止した。 |
| 画面遷移とオーバーレイの責務 | 一部対応 | プレイ画面から離れる処理を `showView()` へ集約し、ゲーム・答え再生・デイリー計測を終了するよう統一。全オーバーレイの状態機械化は、カウントダウン・結果・反則・ログインでライフサイクルが異なるため見送った。 |
| 文字列更新と動的UI更新 | 対応済み | `refreshLocalizedUI()` に表示中ビュー・目標・ストア・プレイ・答えビューア・設定の再翻訳を集約。言語変更だけではホームの画面入場アニメーションを再発火しない。 |
| ホーム遷移ロックの状態 | 対応済み | `homeControlsLocked` / `homeHardLock` を `homeLockState` と `homeInputLocked()` に統合。通常スライドとクリア後の保護区間を単一状態で管理する。 |
| プレイ中の進捗リセット | 対応済み（破壊的実操作は未実施） | リセット時に答え再生・ゲームセッション・デイリー計測・結果表示を終了し、保存値消去後はレベル1のホームへ戻す。購入状態とヒント残数は従来どおり消さない。 |
| デイリー状態の離脱・再訪 | 対応済み | 計測開始時刻とカウントダウンタイマーを `dailyRun` にまとめ、プレイ離脱・再挑戦開始時に破棄する。クリア時だけ経過時間を確定する。 |
| 複数タブ間の永続状態同期 | 見送り | 再現済みの進捗4キーは現行 `storage` リスナーで解決済み。ヒント等の加算値は通知だけでは同時更新の lost update を解決できず、購入権利はRevenueCatが正なので、全状態を一律ストア層へ入れるのは過剰かつ危険。 |

### 未確認候補: デイリー中の日付跨ぎ

問題点: デイリー問題の開始日をセッションに保持していない。日付変更前に開始した問題を翌日にクリアすると、前日の問題で当日分の記録・報酬を得られる可能性がコード上にある。

影響範囲: `startDailyPuzzle()`、ゲームセッション、`checkClear()`、`handleDailyClear()`、共有文言とデイリーハブ。

リファクタリング案: デイリー開始日をゲームセッションへ保存し、クリア時に当日と一致する場合だけ記録・報酬を確定する。不一致時のUX（当日ハブへ戻す、記録対象外と表示する等）を決めてから実装する。

現時点の確度: 中。コード上の経路は確認したが、端末時計を跨ぐ実ブラウザ再現と期待UXの合意は未実施。

## 2026-08-24

### 非同期処理とゲーム状態の所有権を整理する

対象: `web/app.js` の `G`、`AV`、`dailyMode`、`tsumiTimer`、ホーム遷移タイマー。

クリア演出中にホームへ戻って次の問題を開くと、古い `tsumiTimer` が新しい画面へ遅れて作用する状態をブラウザで再現した。また、移動アニメーション中にホームへ戻ると、`await` 後の古い `doMove()` がクリア処理を続けてホームを遅れてロックする競合も再現した。今回の修正ではタイマーを画面遷移・問題初期化時にキャンセルし、ゲーム世代番号で古い非同期移動を無効化している。今後はゲームセッション単位のID、または状態オブジェクトにタイマーと非同期処理を所有させ、古いセッションの完了処理を無効化できる構造へ整理する。

### 画面遷移とオーバーレイの責務を統合する

対象: `showView`、`goHomeFromHeader`、`openSettings`、`openStats`、`openStore`、各オーバーレイの開閉処理。

デイリー開始カウントダウン中に別画面へ移動すると、カウントダウン完了後にデイリー問題が勝手に開く状態をブラウザで再現した。今回の修正では画面遷移・設定・統計・ストア・説明オーバーレイから共通キャンセル処理を呼ぶようにした。画面遷移、オーバーレイ、タイマー停止を一つの遷移管理にまとめると、同種の取りこぼしを減らせる。

### 文字列更新と動的UI更新を統一する

対象: `fillI18n`、`relocalize`、`updateInfo`、`updateAnswerBar`、`renderStats`、`renderStore`。

言語切替時に動的に生成したARIAラベルだけ旧言語のまま残る問題を確認・修正した。静的属性と動的描画が別々の更新経路を持っているため、翻訳キーから表示文言とアクセシビリティ属性を同時に生成する仕組みへ整理する。

### ホーム遷移ロックの状態を単一化する

対象: `homeControlsLocked`、`homeHardLock`、`homeTransition`、ホームの矢印ボタンとスワイプ処理。

レベル送りのアニメーション中に「次へ」を高速で2回押すと、遷移中のロック状態が入力経路に共有されず、1回の操作で2レベル進んで中間レベルを飛ばす状態をブラウザで再現した。今回の修正ではボタンの無効化・矢印ハンドラ・スワイプ判定に `homeControlsLocked` を反映した。今後は `homeControlsLocked` と `homeHardLock` の二重管理を、遷移状態オブジェクトと単一の入力ガードへ整理する。

## 要追加検証（2026-08-25）

### プレイ中の進捗リセット

`resetProgress()` は保存済みのクリア記録を消す一方、プレイ中の `G`、`dailyMode`、`dailyRunStart` を終了させない。高レベル問題のプレイ中にリセットすると、リセット後もその問題をクリアできる可能性がある。ローカル進捗の削除を伴うため、ブラウザでの実操作は確認を取ってから検証する。

### デイリー状態の離脱・再訪

デイリーを途中離脱して再訪する経路は確認したが、クリア後のハブ表示では連続日数とタイム表示に目視上の不整合は再現しなかった。`dailyMode` と `dailyRunStart` のライフサイクルは、ゲームセッション管理のリファクタ時に併せて再確認する。

### 複数タブ間の永続状態同期を一元化する

問題点: `localStorage` の状態がクリア記録・最短記録・解放位置・ヒント・購入・デイリーなどに分散し、多くは起動時にメモリへ読み込んだ後の更新経路が個別化している。今回、別タブのクリア後も元タブのレベルロック表示が更新されない問題を再現し、進捗3種だけを `storage` イベントで同期した。

影響範囲: `web/app.js` の各保存キー、ホーム・一覧・目標・ストア・ヒント残数・デイリー表示。現時点で実害を再現したのはクリア・最短・解放状態の表示で、ヒント・購入・デイリーの別タブ同期は未確認。

リファクタリング案: 保存キーごとの読み込み・書き込み・検証・変更通知を小さな永続ストア層へまとめ、同一タブ更新と `storage` イベントの双方から同じ購読処理を呼ぶ。画面側は必要な状態だけを購読して再描画する。

現時点の確度: 中。進捗表示の不整合は実ブラウザで確認済みだが、他の保存状態に同じ対応が必要かは利用形態と実機要件を踏まえた追加検証が必要。
